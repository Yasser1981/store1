# أرشيف أوامر العمل – نسخة قسم التخطيط

برنامج لأرشفة أوامر العمل في **الشركة العامة لتوزيع كهرباء الفرات الأوسط – فرع توزيع كهرباء كربلاء المقدسة**.

- يعمل على Windows 10 و 11 (64-bit) بدون إنترنت وبدون تنصيب.
- قاعدة البيانات ملف منفصل (`data/workorders.db`) لا يتأثر عند تحديث البرنامج.
- لكل إصدار رقم يظهر في عنوان النافذة (الإصدار الحالي في `workorders/__init__.py`)، ولقاعدة البيانات رقم هيكل يُحدَّث تلقائياً.

## تحميل ملف exe
يُبنى ملف exe تلقائياً على GitHub عند كل رفع للكود:
1. افتح صفحة المستودع على GitHub ← تبويب **Actions**.
2. اختر آخر تشغيل ناجح (علامة ✓ خضراء) باسم **Build Windows EXE**.
3. في أسفل الصفحة، قسم **Artifacts**، حمّل الملف `WorkOrders-Planning-v…`.
4. فك الضغط، وستجد مجلد `WorkOrders` وفيه `WorkOrders.exe` وملف تعليمات `README.txt`.

تعليمات الاستخدام والتحديث والنقل لحاسبة أخرى موجودة في [`dist_files/README.txt`](dist_files/README.txt).

## هيكل البرنامج
| الملف | الوظيفة |
|---|---|
| `workorders/constants.py` | القوائم الثابتة (أنواع الأوامر، أنواع العمل، الجهد، الحالات، القطاعات والمواد الأولية) |
| `workorders/models.py` | نموذج أمر العمل، وحساب الحالة والتدوير تلقائياً |
| `workorders/validation.py` | قواعد منع الأخطاء (تكرار الرقم، تسلسل المراحل والتواريخ...) |
| `workorders/db.py` | إنشاء قاعدة البيانات وتحديث هيكلها بين الإصدارات |
| `workorders/repository.py` | الحفظ والقراءة من قاعدة البيانات |
| `workorders/reports.py` / `export.py` | بناء التقارير وتصديرها (HTML للطباعة و PDF، و Excel) |
| `workorders/backup.py` | النسخ الاحتياطي والاسترجاع |
| `workorders/ui/` | الشاشات |
| `tests/` | الاختبارات الآلية |

## قواعد العمل المطبقة
- **رقم أمر العمل** لا يتكرر في نفس السنة حتى لو اختلف النوع، ولا يُستخدم ما دام أمر العمل الذي يحمله (من سنة سابقة) غير منتهٍ. المنتهي هو المغلق أو الملغى (بكتاب أو تلقائياً) أو المرفوض.
- **الحالة** تُحسب تلقائياً: معدّ ← مرفوع (لم ترد الموافقة) ← موافق عليه ← مباشر به ← مغلق، أو مرفوض، أو ملغى بكتاب (الإلغاء ممكن في أي مرحلة قبل الغلق).
- **الإلغاء التلقائي**: أمر العمل الذي لم يُباشر به حتى نهاية سنته يصبح «ملغى تلقائياً» عند حلول السنة الجديدة، ويتحرر رقمه. لذلك يجب أن يكون تاريخ المباشرة ضمن سنة أمر العمل.
- **التدوير** يُحسب تلقائياً: أمر العمل المباشر به الذي لم يُغلق حتى نهاية سنة المباشرة يُعتبر مدوّراً إلى السنة التالية، وهكذا.
- **تاريخ المباشرة الفعلي** يُملأ افتراضياً من تاريخ الأمر الإداري بالمباشرة ويمكن تعديله (قد يسبقه أو يليه)، وهو المعتمد في التدوير والإلغاء التلقائي وتسلسل التواريخ.
- **المواد الحاكمة** لأوامر عمل الشبكة الكهربائية فقط.
- **التسلسل**: لا يُدخل الرد قبل كتاب الرفع، ولا المباشرة قبل الموافقة، ولا الغلق قبل المباشرة. كل تاريخ لا يسبق تاريخ المرحلة التي قبله، ولا يُقبل تاريخ بعد تاريخ اليوم.
- **التصنيف الفني** (استحداث / تأهيل مغذي) لجهد 33 و 11 ك.ف فقط، و**قطاع التوزيع** لجهد 11 ك.ف والضغط الواطئ فقط.
- لا يُشترط اختيار رئيس لجنة التنفيذ قبل إدخال أمر المباشرة.
- **الكلف**: أجور العمل، وكلفة المواد غير المتوفرة، والكلفة الكلية للمواد تُدخل عند الإعداد (وتُعدَّل بعد الموافقة عند الحاجة)، والكلفة الكلية التخمينية = الكلفة الكلية للمواد + أجور العمل (تلقائياً). الكلفة الكلية للمواد لا تقل عن كلفة غير المتوفرة.
- **مجموعات أوامر العمل**: تأشير أي عدد من الأوامر لحساب مجموع كلفها (مبالغ التخصيص) وموادها الحاكمة وتفصيلها، وحفظها كمجموعة باسم لاستخدامها لاحقاً وفي التقارير.
- **المباشرة قبل تاريخ الموافقة** مسموحة كحالة استثنائية مع تنبيه وتأكيد عند الحفظ، وتُميَّز بعلامة ⚠ وفلتر خاص للمراجعة.

### إضافة تعديل على قاعدة البيانات في إصدار لاحق
1. أضف دالة `_migration_2` في `workorders/db.py` تحتوي التعديل (مثل `ALTER TABLE ... ADD COLUMN ...`).
2. سجّلها في `MIGRATIONS` وارفع `SCHEMA_VERSION` إلى 2.
3. ارفع رقم الإصدار في `workorders/__init__.py` وسجّل التغيير في `CHANGELOG.md`.

عند تشغيل الإصدار الجديد على قاعدة بيانات قديمة، يأخذ البرنامج نسخة احتياطية منها أولاً ثم يحدّثها تلقائياً.
